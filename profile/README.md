# 47Geese

**Free, open-source software for health sciences education. Built around real problems.**

Health sciences schools (nursing, medicine, pharmacy and the allied health professions) prepare the people our health system depends on. Many do it on tight budgets, with software that is expensive, closed, or built in-house and hard to keep going. 47Geese builds focused tools for the problems these schools actually face, and gives them away as open source.

🌐 **[47geese.com](https://47geese.com)**

## How our tools work

- **One problem, solved well.** Each tool does one job. A school can adopt just the piece it needs, beside the LMS and systems it already runs.
- **Free and open source.** Use it as it is, run it yourself, or adapt it to fit.
- **Works with everything else.** Open standards (LTI, CSV and the formats schools already use) so data moves between our tools and existing systems.
- **AI-first.** AI assistants and agents can use every tool through MCP and A2A, acting as the person using them and never above their access.
- **Careful with data.** Each tool holds only what it needs and says so plainly.

## Projects

| --- | --- | --- |
| **Quire** | Is our curriculum built to produce the competencies we promise, and can we prove it to accreditors? AI proposes how curriculum maps to competency frameworks, and people confirm it. | In development |

Open-source communication between the two: any A2A agent joins from a link, says what it's doing, asks questions and waits for approval, under permissions people can take back. Checks for patient details before anything is posted. | In development |

| **Exam blueprints** | Knowing which competencies an exam actually tests, before learners sit it. | In discussion |

| **Accreditation self-studies** | Writing a self-study from evidence instead of assembling it from memory. | In discussion |

## Why 47Geese exists

Software is now much cheaper to build. Understanding a problem well enough to solve it isn't. That understanding is where we put our effort, with the educators and staff who live these problems:

1. Understand the problem
2. Explore possibilities
3. Experiment and learn
4. Share what works
